02. Problem Statement
Critical Failure Modes in Handwritten Vision Systems
1. Train-Inference Skew
  • Native MNIST tensors are pre-centered by center-of-mass into a 20x20 box.
  • Raw browser canvas drawings have arbitrary thickness, offset centroids, and inverted colors.
  • Without canonical preprocessing, spatial activations miss convolutional receptive fields.
2. Overconfident Softmax
  • Standard Softmax outputs exponentiate uncalibrated logits into deceptive pseudo-probabilities.
  • Models routinely emit >98% confidence on out-of-distribution noise or invalid scribbles.
  • Absence of calibration metrics (ECE) and Shannon entropy makes automated delegation hazardous.
3. Opaque Latent Decisions
  • Users and auditors receive discrete categorical integer outputs without spatial attribution.
  • Impossible to verify if the classifier attended to genuine digit anatomy or background artifacts.
  • Modern deployment standards mandate Explainable AI (XAI) transparently mapped in real time.
03. Motivation
Why Handwritten Digit Intelligence Requires Calibrated Forensics
High-Stakes Document Transcription

In financial checks, tax forms, postal sorting, and academic grading, an undetected misclassification has serious legal and economic consequences. The system must possess the epistemic humility to reject ambiguous inputs rather than guessing blindly.

Probabilistic Trust & Safe Delegation

Modern autonomous workflows require reliable confidence scores that match empirical accuracy. Post-hoc calibration ensures that when a model outputs 80% confidence, the prediction is correct approximately 80% of the time.

Visual Auditability & Explainability

Regulatory compliance (e.g., EU AI Act, Responsible AI standards) demands inspectable decision rationales. Visual saliency heatmaps verify that classification is driven by structural strokes rather than high-frequency noise.

Academic & Engineering Rigor

Elevates a standard benchmark into a production-grade machine learning system through rigorous software architecture, deterministic data hygiene, and automated regression testing.

05. ML Formulation
Mathematical Problem Formulation & Formal Metric Space
Input & Label Spaces
  • Input Space: X in [0, 1]^(28x28x1), normalized single-channel floating-point matrices.
  • Feature Space: x in R^784 for classical classifiers.
  • Label Space: Y = {0, 1, ..., 9}, a 10-class mutually exclusive discrete set.
  • Domain: D = {(X_i, y_i)} drawn i.i.d. from empirical handwriting distribution.
Loss & Optimization
  • Loss Criterion: Sparse Categorical Cross-Entropy (Multinomial Negative Log-Likelihood):
  • L_CE = - (1/N) * sum_i log( exp(z_{i, y_i}) / sum_j exp(z_{i, j}) ).
  • Optimizer: Adam with mini-batch updates (beta1=0.9, beta2=0.999, eps=1e-7).
  • Regularization: Dual spatial dropout (p=0.25) and dense dropout (p=0.40).
Evaluation Metric Space
  • Accuracy = (TP + TN) / Total.
  • Macro F1-Score = (1/10) * sum_c F1_c.
  • Expected Calibration Error (ECE) across M empirical confidence bins.
  • Epistemic Entropy: H(p) = - sum_j p_j * log(p_j) nats.

09. Preprocessing Pipeline
The 7-Stage Canonical Preprocessing Invariant
7-Stage Pipeline Sequence
1. Grayscale Decoding: Decodes base64 strings into single-channel arrays.
2. Contrast Inversion: Detects polarity; inverts light backgrounds to black.
3. Otsu Thresholding: Inter-class variance binarization removes anti-aliasing.
4. Bounding Box Crop: Isolates tightest rectangle enclosing active strokes.
5. Aspect-Ratio 20x20 Fit: Scales longer dimension to 20px preserving ratio.
6. Center-of-Mass Centering: Translates spatial centroid to (13.5, 13.5).
7. Float32 Tensor: Emits normalized (1, 28, 28, 1) float32 array in [0, 1].
Centroid Invariant & Edge Cases
  • Spatial Moments: Centroid x_c = M10/M00, y_c = M01/M00 computed on pixel masses.
  • Offset Translation: Delta_x = 13.5 - x_c, Delta_y = 13.5 - y_c applied via affine shift.
  • Edge Hardening: Empty canvas (<18 active pixels) returns blank warning without inference.
  • Noise Rejection: Isolated single-pixel noise clusters filtered during component analysis.
  • Unit Test Verification: 33 dedicated pytest unit tests verify mathematical stability.
